# v0.8 evaluation manifest addendum

## Scope

The `agent-eval --manifest PATH` option now writes a reproducibility sidecar before the matrix
starts:

- it records the adapter, model names, query/fragment-free endpoint, temperature, timeout,
  retry count, API-key environment variable name, full evaluation configuration, and an optional
  repository revision from `CONTEXTOPT_GIT_REVISION` or `GITHUB_SHA`;
- it is intentionally separate from the durable result schema and checkpoint ledger;
- only the environment variable name is recorded; the API key value is never serialized;
- the CLI tests cover manifest creation alongside JSON, Markdown, HTML, and checkpoint outputs.

## Why

A result ledger without model and runtime identity is difficult to reproduce or audit. The
sidecar makes fixed-provider comparisons reviewable while keeping credentials out of artifacts.
It also makes a resumed matrix visibly tied to the same configuration that created its
checkpoint.

## Evidence

```text
python -m unittest tests.test_agent_search_eval -v
python -m ruff check src tests
python -m mypy src/contextopt
python -m unittest discover -s tests -q
python scripts/ci_checks.py
```

## Claim boundary

The manifest records identity; it does not guarantee provider determinism, exactly-once calls,
statistical power, or model quality. Endpoint query strings and fragments are removed, but users
should still avoid putting credentials in a base URL.
