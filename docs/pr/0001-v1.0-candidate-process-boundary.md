# PR note: v1.0 candidate process lifecycle boundary

## Why

The coding-agent search loop already materialized candidates in temporary workspaces, but its
trusted test command inherited the full host environment and `subprocess.run(timeout=...)` only
guaranteed that the direct process was killed. A long-running test could therefore leak common
credentials or leave descendants running after a timeout.

## What changed

- Launch every candidate/test command in a fresh process group without a shell.
- On POSIX, terminate the process group with `SIGTERM`/`SIGKILL`; on Windows, use a
  kill-on-close Job Object when the host permits it, with a best-effort fallback to `taskkill`.
- Replace the inherited environment with a copy that removes common credential names such as
  `CONTEXTOPT_API_KEY`, `OPENAI_API_KEY`, `*_TOKEN`, `*_SECRET`, and `*_PASSWORD` while keeping
  normal runtime variables such as `PATH`.
- Preserve bounded stdout/stderr hashing and turn timeout cleanup into an explicit
  `process group terminated` observation.
- Add provider-free tests for credential scrubbing and descendant termination.

## Validation

```text
python -m unittest tests.test_branch_executor -v
python scripts/ci_checks.py
```

## Claim boundary

This is a process-lifecycle and accidental-secret-leak boundary, not an OS security sandbox.
Candidate commands remain trusted host code and can access resources available to that host.
Untrusted repositories still require a container or virtual machine.
