# v0.8 合并感知候选快照补充说明

## 本次范围

这次后续变更为独立 solver 分支增加可选、证据优先的合并步骤：

- `three_way_merge` 把每个候选快照与同一个根快照进行三方比较；
- 未变化路径、两边相同修改、以及只有一边修改的路径可以安全合并；
- 同一路径的不同修改生成 `MergeConflict`，记录 base/left/right 指纹，不产生部分工作区；
- `OrchestrationConfig(merge_policy="disjoint")` 在可见 oracle 前加入有界合并候选，合并候选
  消耗共享 candidate/test budget，并写入 `solver.merge` 事件；
- 编排 CLI 暴露 `--merge-policy {disabled,disjoint}`；
- 确定性测试覆盖冲突拒绝和通过测试的 disjoint 合并。

## 为什么做

独立 solver 分支经常修改不同文件。只分别测试每个分支会丢掉兼容组合，而对同一路径
冲突进行文本猜测又不安全。三方合并把兼容性判断显式化，最终仍交给可执行 oracle
判断组合快照是否真的可用。

## 验证证据

~~~text
python -m unittest tests.test_orchestrator -v
python -m ruff check src tests
python -m mypy src/contextopt
python -m unittest discover -s tests -q
python scripts/ci_checks.py
~~~

## 边界

这是对已经返回的完整候选快照做有界合并，不会并发调用 provider，也不解决语义冲突，
不提供 OS sandbox，更不能证明真实模型上的多 Agent 价值。每个合并候选仍必须通过相同
的可见测试 oracle，并受共享预算约束。
