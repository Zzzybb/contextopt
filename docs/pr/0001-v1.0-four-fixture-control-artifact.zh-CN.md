# PR #1 — v1.0 四任务控制产物与 adapter smoke

## 改动

- 在 `experiments/v1.0-acm-math-4-fixtures/` 提交全部四个 ACM/数学 fixture 的 `3` 次重复
  确定性控制 ledger。
- 更新手动 real-provider workflow 的输入说明，列出完整 fixture registry：`two-sum`、
  `extended-gcd`、`merge-intervals`、`modular-inverse`。
- 将本地 OpenAI-compatible adapter smoke 从一个任务扩展到四个任务，继续校验请求格式、
  authorization、idempotency key、visible oracle 和 hidden grader。
- 增加中英文实验说明；生成的 JSON/Markdown/HTML/checkpoint/manifest 是获得授权后真实
  provider 运行应对照的固定基线，manifest 固定源码 revision
  `4794ddbe6dc856939631b4f6cb1ead37c75d4c6b`。

## 验证

```text
python -m unittest tests.test_agent_search_eval.AgentEvaluationTests.test_real_adapter_matrix_path_works_with_local_compatible_provider
python -m contextopt agent-eval --fixtures all --repetitions 3 ...
```

控制产物包含 `36` 个 cell：`single_pass` 接受 `0/12`，`best_of_n` 与 `orchestrated` 都
接受 `12/12` 个 visible cell，并通过 `12/12` 个独立 hidden grader。本地 adapter smoke
在不访问外部 provider 的情况下覆盖全部四个 fixture。

## 边界

控制 ledger 仍是确定性的 scripted baseline，本地 HTTP server 也只是协议 fixture。两者都
不能证明真实模型代码能力、provider 稳定性、多智能体因果价值或生产安全。真实对比仍需固定
provider、model、prompt、budget，并在获得授权后至少运行三次。
