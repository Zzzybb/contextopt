# PR 说明：v1.0 无 provider key 的多模型矩阵演示

## 改动内容

- 新增 `scripts/run_model_matrix_demo.py`：生成两份确定性的四任务、三次重复 bundle，并把它们
  送入 `agent-eval-compare`。
- 新增 `examples/model_matrix_demo/` 双语使用说明，记录生成产物和明确的控制副本边界。
- 扩展 `scripts/ci_checks.py`，让仓库脚本也接受 lint 和格式检查，并修复因此暴露的既有导入
  顺序/换行问题。
- 将 scripted provider 缺失的身份渲染为 `n/a`，而不是 Python 字符串 `None`，避免作品集报告
  把控制副本误读成真实模型名。

## 为什么做

真实 provider workflow 必须要求 API key，但面试官或贡献者仍应能立即看到完整的“采集 → 分析”
链路。这个 demo 在无网络条件下复用同一套 manifest 匹配、protocol fingerprint、配对比较和
JSON/Markdown/HTML 渲染器，同时明确不把 scripted control 当成模型证据。

## 验证

~~~text
python scripts/run_model_matrix_demo.py --output-dir build/model-matrix-demo
python -m unittest tests.test_model_matrix
python -m unittest tests.test_model_matrix_demo
python scripts/ci_checks.py
~~~

## 结论边界

两个 label 是确定性的控制副本，不是独立真实模型。生成的矩阵只能证明管线和记账正确，不能
证明模型能力、泛化能力、provider 行为或生产安全。
