# PR 说明：v1.0 配对多模型矩阵分析

## 为什么做

真实 provider workflow 每次运行会产生一份 report 和 manifest。手工比较这些文件时，很容易
把不同 fixture、预算、源码 revision 或 sandbox 策略的结果混在一起，再把它称为模型比较。
因此在做任何跨模型结论前，需要一个独立且严格的分析步骤。

## 改动内容

- 增加 `agent-eval-compare`：接收带显式 label 的多个 `REPORT MANIFEST` bundle，并用规范化
  SHA-256 fingerprint 拒绝协议漂移；
- 在合并前校验每份 manifest 与 report config、adapter、仓库 revision、运行时限制、sandbox
  和 container image 一致；
- 保留每个模型的策略 summary 和配对差值，再输出跨模型方向一致性、均值和观测方差；
- 输出 JSON、Markdown、自包含 HTML 分析产物；聚合产物不会复制 provider 凭据或原始 ledger。

## 验证

```text
python scripts/ci_checks.py
python -m unittest tests.test_model_matrix
```

示例：

```text
python -m contextopt agent-eval-compare \
  --bundle model-a artifacts/model-a.json artifacts/model-a.manifest.json \
  --bundle model-b artifacts/model-b.json artifacts/model-b.manifest.json \
  --output model-matrix.json --markdown model-matrix.md --html model-matrix.html
```

## 结论边界

这是一层配对 artifact 防漂移检查和描述性的泛化摘要。它不会把不兼容实验的 raw cell 混合，
不会拟合 random-effects 模型，不做多重比较校正，也不能证明通用代码能力。可信的探索性
比较仍然要求真实 provider 采集、独立 hidden tests、固定 prompt/tool/预算，以及至少三次重复。
