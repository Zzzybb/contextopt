# PR #1 — v1.0 multi-agent provider adapter smoke

## What changed

- Added a deterministic local OpenAI-compatible HTTP fixture that returns the strict
  planner, solver, and reviewer JSON contracts used by the orchestrator.
- Exercised the real HTTP adapter path for all four ACM/math fixtures with distinct
  planner/solver/reviewer model names, authorization, endpoint, and idempotency-key
  assertions.
- Kept the smoke provider-free: it binds only to loopback, uses no API key from the
  environment, and runs the independent hidden grader after reviewer-gated acceptance.

## Validation

```text
python -m unittest tests.test_agent_search_eval.AgentEvaluationTests.test_real_adapter_orchestrated_matrix_path_works_with_local_provider
python -m unittest discover -s tests
python scripts/ci_checks.py
```

The smoke accepts all four fixtures and records exactly one planner, one solver, and one
reviewer request per fixture. Every request uses `/v1/chat/completions`, the configured
authorization header, a unique `contextopt-*` idempotency key, and the expected role model.

## Claim boundary

This is an adapter and orchestration-contract smoke, not evidence of model quality,
provider reliability, latency, cost, or multi-agent causal improvement. The real-provider
matrix remains a separate manually authorized experiment with a fixed model, prompt, budget,
and at least three repetitions.
