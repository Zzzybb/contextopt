# PR #1 — v0.9 local OpenAI-compatible provider smoke

## Why

The real-provider benchmark must remain opt-in and secret-free in CI, but the adapter-to-
`agent-eval` boundary should still be exercised automatically. A local HTTP fixture now
proves that the actual OpenAI-compatible request path can produce a complete candidate and
pass the visible/hidden oracle gates.

## What changed

- Added a local Chat Completions-compatible test server to the agent evaluation suite.
- Runs the real `OpenAICompatibleModel` through `run_agent_evaluation` for the ACM two-sum
  fixture, including hidden grading.
- Asserts endpoint shape, bearer authorization, stable idempotency header, model name, and
  accepted candidate outcome.
- No external network, provider account, or secret is used by CI.

## Claim boundary

This is an adapter and harness contract smoke, not model-quality evidence. The response is a
deterministic fixture generated by the local test server. The real-provider matrix remains
manual and requires an explicitly supplied `CONTEXTOPT_API_KEY`.
