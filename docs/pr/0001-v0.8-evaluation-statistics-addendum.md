# v0.8 evaluation statistics addendum

## Scope

This follow-up makes the repeated coding-agent report easier to interpret without changing
the raw evaluation ledger:

- `wilson_interval` computes a bounded descriptive 95% interval for each visible success rate;
- `AgentEvalComparison` and `build_agent_eval_comparisons` pair the same fixture and repetition
  across strategies, then count wins, losses, and ties and calculate visible/hidden outcome
  deltas plus mean test-call and token deltas;
- console, Markdown, and HTML renderers expose the interval and paired comparison table;
- hidden deltas are reported only when both paired runs actually executed the independent hidden
  grader; missing hidden observations remain `n/a` rather than being treated as failures;
- tests cover the deterministic fixture signal, bounded intervals, and both report renderers.

## Why

A single success-rate point estimate hides sample size and makes an unpaired strategy comparison
easy to overstate. Pairing by fixture and repetition controls the most obvious source of noise,
while the Wilson interval makes the uncertainty of tiny matrices visible. The raw JSON schema
remains unchanged: comparisons are derived views over the auditable run ledger.

## Claim boundary

These are descriptive statistics, not a significance test or a claim of general model quality.
The checked-in scripted matrix has one repetition and two small ACM/math fixtures. A credible
real-provider comparison still requires a fixed provider/model/prompt/fixture/budget matrix,
at least three exploratory repetitions, preserved failed trajectories, and more runs when the
observed variance warrants them.
