# v0.8 evaluation-matrix checkpoint addendum

## Scope

This follow-up makes repeated coding-agent evaluations durable across provider or process
interruptions:

- `AgentEvalCheckpoint` stores the validated matrix configuration, fixture ids, and completed
  fixture/strategy/repetition cells without serializing hidden grader source;
- `write_agent_evaluation_checkpoint` uses a same-directory temporary file, `fsync`, and atomic
  replace; the checkpoint is written before the first cell and after every completed cell;
- `run_agent_evaluation(..., checkpoint_path=..., resume=True)` validates configuration and
  fixture identity, reuses durable cells, and executes only missing observations;
- the public CLI exposes `--checkpoint PATH` and `--resume`, and the existing JSON/Markdown/HTML
  report is emitted only after the configured matrix is complete;
- a stopped provider call before its cell checkpoint is recorded may run again, so this is
  at-least-once recovery rather than exactly-once provider execution.

## Why

Real-model repetitions are the expensive part of a credible Agent comparison. A process-level
checkpoint prevents a late failure from discarding earlier fixture/strategy cells and makes the
full ledger reviewable. The checkpoint stores accounting data, not credentials or hidden grader
source, and configuration mismatch is rejected instead of silently mixing experiments.

## Evidence

Tests create a two-repetition matrix, verify the atomically written checkpoint, replace it with
a one-cell partial checkpoint, and resume to the same self-consistent report. The public CLI test
also writes the checkpoint next to JSON, Markdown, and HTML outputs:

```text
python -m unittest tests.test_agent_search_eval -v
python -m ruff check src tests
python -m mypy src/contextopt
python -m unittest discover -s tests -q
python scripts/ci_checks.py
```

## Claim boundary

This improves experiment durability, not provider idempotency, benchmark power, or model quality.
A model request that completed before the atomic cell replacement can be repeated after a crash.
The checkpoint does not make host test commands safe, and it does not turn fixed ACM/math fixtures
into evidence of generalization, latency, reliability, security isolation, or production safety.
