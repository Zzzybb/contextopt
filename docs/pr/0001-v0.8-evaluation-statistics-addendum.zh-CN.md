# v0.8 评测统计补充说明

## 本次范围

这次后续变更不修改原始评测 ledger，只让重复代码 Agent 报告更容易解释：

- `wilson_interval` 为每个可见成功率计算有界的描述性 95% 区间；
- `AgentEvalComparison` 与 `build_agent_eval_comparisons` 按相同 fixture 和 repetition
  配对不同策略，统计胜/负/平，并计算可见/隐藏结果差值以及平均测试调用和 token 差值与
  观测到的总体标准差；
- console、Markdown、HTML 报告都展示区间和配对比较表；
- 只有当一对运行都真正执行了独立 hidden grader 时才计算 hidden 差值；缺失 hidden
  observation 保留为 `n/a`，不会被当成失败；
- 测试覆盖确定性 fixture 信号、有界区间和两种报告渲染器。

## 为什么做

只看成功率点估计会隐藏样本量，也容易把未配对的策略差异说得过头。按 fixture 和
repetition 配对可以控制最直接的噪声来源，Wilson 区间可以把小矩阵的不确定性显式
展示出来。原始 JSON schema 保持不变：比较结果是对可审计运行 ledger 的派生视图。

## 验证证据

python -m unittest tests.test_agent_search_eval -v
python -m ruff check src tests

~~~

## 边界

这是描述性统计，不是显著性检验，也不构成真实模型能力结论。仓库中的脚本矩阵只有
一次 repetition 和两个小型 ACM/数学 fixture。可信的真实 provider 比较仍需要固定
provider/model/prompt/fixture/budget 矩阵，至少三次探索性 repetition，保留失败轨迹，
并根据观测方差增加运行次数。
