# PR note: v1.0 workspace knowledge-base index

## Why

The semantic-memory layer could persist manually saved procedures and facts, but a coding
Agent still had no reproducible way to turn the repository itself into a searchable knowledge
base. That left the most relevant source evidence outside the cross-run context pipeline.

## What changed

- Added `KnowledgeIndexConfig`, `KnowledgeIndexReport`, and `index_workspace` in
  `contextopt.runtime.knowledge`.
- Added the `knowledge-index` CLI command with explicit file, byte, extension, directory, and
  dotfile bounds.
- Chunks carry a relative path/line-range header, `source_refs`, a `knowledge-chunk-v1` tag,
  and a content-derived identity in the existing append-only semantic-memory ledger.
- Re-indexing reuses unchanged chunks and appends invalidation events for changed or removed
  chunks; reopening the store preserves the same retrieval view.
- Added an auditable JSON/Markdown report with file counts, skip reasons, chunk accounting, and
  a snapshot fingerprint.
- Added English/Chinese guides, PR notes, and tests for repeatability, invalidation, bounds,
  CLI artifacts, and cross-process reopen.

## Claim boundary

The index is a deterministic lexical source projection. It demonstrates provenance, freshness,
bounded retrieval, and persistence; it does not claim embedding quality, automatic summarization,
that a model used every retrieved chunk, or improved coding success.
