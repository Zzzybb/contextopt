# v0.9 follow-up — durable cross-run semantic memory

## Summary

This follow-up adds an explicit semantic-memory boundary to ForgeAgent. The existing
`versioned-v1` observed-memory projection remains the source of truth for the current
workspace transcript; this new store is an advisory cross-run notebook that the agent
must query explicitly.

## Changes

- Add `SemanticMemoryStore`, an append-only schema-1 JSONL event log with the same
  corruption-evident event chain and cross-process lease used by runtime traces.
- Store typed `fact`, `decision`, `procedure`, and `failure` entries with scope, tags,
  confidence, source run/reference metadata, content digests, idempotent identity, and
  explicit invalidation/supersession states.
- Add deterministic lexical retrieval with matched-term evidence, scope inheritance from
  `global`, stable tie-breaking, and a persisted revision/fingerprint.
- Expose `memory_search` and (when `--allow-write` is enabled) idempotent `memory_save` plus
  explicit `memory_invalidate` through `WorkspaceTools`; save can supersede an earlier entry,
  and safe replay treats all three operations as retryable.
- Add `contextopt run/resume --memory-store PATH`, include the store identity in the
  tool configuration fingerprint, and document that memory is a hint rather than proof
  about the mutable workspace.
- Add unit coverage for append-only replay, deduplication, scopes/tags, supersession,
  invalidation, tool output, permission-gated saving, and two fresh Agent runs sharing one store.
- Check in `examples/semantic_memory_demo`, a writer/reader pair that reproduces the cross-run
  flow without a provider key.

## Claim boundary

The store deliberately has no embedding dependency, automatic summarizer, or learned
confidence calibration. Lexical retrieval demonstrates durable memory plumbing and
auditable provenance; it does not establish that memory improves model coding success.
Concurrent writers are rejected by the store lease, and an interrupted `memory_save` is
safe to retry because its identity is content-derived.
