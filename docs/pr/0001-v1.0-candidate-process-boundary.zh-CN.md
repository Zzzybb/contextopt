# PR 说明：v1.0 候选进程生命周期边界

## 为什么做

代码 Agent 搜索循环已经把候选放进临时 workspace，但此前可信测试命令会继承完整宿主环境，
`subprocess.run(timeout=...)` 也只保证直接父进程被终止。长时间运行的测试因此可能暴露常见凭据，
或在超时后留下仍在运行的子进程。

## 改动内容

- 每个候选/测试命令都以无 shell 的方式启动在独立进程组中；
- POSIX 使用 `SIGTERM`/`SIGKILL` 终止进程组；Windows 在主机允许时使用 kill-on-close
  Job Object，并以 `taskkill` 作为 best-effort fallback；
- 子进程环境改为宿主环境副本，但会清理 `CONTEXTOPT_API_KEY`、`OPENAI_API_KEY`、`*_TOKEN`、
  `*_SECRET`、`*_PASSWORD` 等常见凭据变量，同时保留 `PATH` 等普通运行变量；
- 保留 stdout/stderr 的有界哈希，并把超时清理记录为显式的 `process group terminated` 观察；
- 增加 provider-free 的凭据清理和子进程终止测试。

## 验证命令

```text
python -m unittest tests.test_branch_executor -v
python scripts/ci_checks.py
```

## 结论边界

这只是进程生命周期和意外凭据泄露边界，不是 OS security sandbox。候选命令仍是可信宿主机代码，
可以访问宿主机允许的资源；不可信仓库仍需要放进 container 或虚拟机。
