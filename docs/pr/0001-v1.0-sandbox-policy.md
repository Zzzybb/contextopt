# v1.0 sandbox policy

## What changed

Add a bilingual candidate-execution sandbox policy that distinguishes trusted host runs, the
hardened opt-in Docker path, and the external VM boundary required for untrusted generated code.
Add a contract test that locks the Docker command's network, capability, privilege, filesystem,
resource, and temporary-directory flags.

## Why

“Docker enabled” is not the same as “secure sandbox.” A coding-agent benchmark needs to state
which kernel, network, mounts, credentials, and resource limits are in scope before its results
can be compared. The policy makes that boundary reviewable and keeps the remaining VM work
explicit instead of silently overclaiming container isolation.

## Validation

- `python -m unittest tests.test_branch_executor -v`
- `python scripts/ci_checks.py`
- GitHub Actions Docker candidate smoke

## Claim boundary

The policy and Docker contract test do not provision or certify a VM, Docker daemon, side-channel
isolation, or provider-side cancellation. They are a reproducible local/CI boundary and an operator
checklist for a future controlled real-model run.
