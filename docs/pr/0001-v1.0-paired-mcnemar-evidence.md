# PR note: v1.0 exact paired-outcome evidence

## Why

The strategy matrix already paired every candidate with the same fixture and repetition, but
the report only exposed wins, losses, and a descriptive outcome delta. A reviewer could see
the direction of a change without a compact measure of how much paired binary evidence was
actually discordant.

## What changed

- Add an exact two-sided McNemar p-value for visible paired outcomes and for each available
  hidden paired cell where both runs have an independent hidden result.
- Persist the values in JSON and render them in Markdown and the self-contained HTML report.
- Keep the raw wins/losses/ties and deltas beside the p-value so the statistic is auditable
  from the fixture/repetition ledger rather than treated as a replacement metric.
- Export and unit-test the small standard-library implementation, including the zero-discordant
  and all-wins cases.

## Validation

```text
python scripts/ci_checks.py
python -m unittest tests.test_agent_search_eval
```

The exact calculation conditions on the discordant-pair count and uses the two-sided binomial
tail under the McNemar null. If no paired hidden results are available in a comparison, the
hidden value is rendered as `n/a` instead of fabricating a result.

## Claim boundary

This is an exploratory paired-outcome diagnostic, not a powered benchmark, a multiple-testing
correction, or evidence that one agent strategy improves general coding/math ability. The
current scripted control artifact has only three repetitions per fixture and deliberately
remains provider-free. Real-provider conclusions still require a fixed model/prompt/tool
matrix, repeated runs, preserved failures, and an explicit analysis plan.
