# PR note: v0.9 real-provider secret scope hardening

## Why

The manual real-provider workflow must make an API call, but the credential should not be
available to unrelated third-party Actions steps such as checkout, setup, or artifact upload.
A job-level secret environment variable unnecessarily widened that exposure.

## What changed

- Remove `CONTEXTOPT_API_KEY` from the job-wide environment.
- Pass it only to the secret-presence validation step and the evaluation command that needs it.
- Keep the revision identity job-scoped and keep uploaded artifacts key-free.
- Add this bilingual change note so the workflow's trust boundary is explicit.

## Validation

```text
python -c "import yaml; yaml.safe_load(open('.github/workflows/real-agent-eval.yml', encoding='utf-8')); print('yaml ok')"
python scripts/ci_checks.py
```

## Claim boundary

This narrows the GitHub Actions environment but cannot protect against a malicious change to the
workflow or a compromised provider. The real-provider workflow remains manual and requires an
operator-controlled repository/environment secret.
