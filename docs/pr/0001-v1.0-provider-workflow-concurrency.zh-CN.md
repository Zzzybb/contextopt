# PR 说明：v1.0 provider workflow 并发门禁

## 改动内容

- 给两个手动 provider workflow 增加按 repository/ref 隔离的 GitHub Actions concurrency group。
- 设置 `cancel-in-progress: false`：已经启动的评测不会被新点击取消，新运行会等待，避免付费
  实验被中途截断或出现重叠 provider 负载。
- 用 workflow contract 测试锁定行为，并补充双语说明。

## 为什么做

真实 provider 矩阵是手动触发，可能消耗配额或费用。浏览器重复点击，或在 UI 缓慢时重试，都会
让同一实验并发运行。串行化可以保持 checkpoint/ledger 的解释一致，也让费用边界清晰。

## 验证

~~~text
python -m unittest tests.test_workflow_contract -v
python scripts/ci_checks.py
~~~

## 结论边界

这是 GitHub Actions 的调度和成本安全门禁，不会取消 provider 请求，不能证明远端 exactly-once
执行，也不能证明模型能力。
