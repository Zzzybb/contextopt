# PR 说明：v0.9 真实 provider secret 作用域收紧

## 为什么做

手动真实 provider 工作流需要 API key，但 credential 不应暴露给 checkout、setup 或
artifact upload 等无关的第三方 Actions step。原来的 job-level 环境变量扩大了不必要的
暴露范围。

## 改动内容

- 从整个 job 的环境变量中移除 `CONTEXTOPT_API_KEY`；
- 只在 secret 存在性校验 step 和真正发起评测的 command step 注入它；
- revision identity 仍保留在 job 级别，上传的 artifact 不包含 API key；
- 补充本中英文变更说明，明确 workflow 信任边界。

## 验证命令

~~~text
python -c "import yaml; yaml.safe_load(open('.github/workflows/real-agent-eval.yml', encoding='utf-8')); print('yaml ok')"
python scripts/ci_checks.py
~~~

## 结论边界

该改动收紧 GitHub Actions 环境，但不能防御恶意修改 workflow 或 provider 被攻破。真实
provider 工作流仍然是手动触发，并要求操作者控制 repository/environment secret。
