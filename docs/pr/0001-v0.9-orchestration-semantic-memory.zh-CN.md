# PR #1 — v0.9 多智能体编排接入语义记忆

## 为什么做

此前 durable-memory 候选只接入单 Agent runtime；planner/solver/reviewer 编排仍只使用
observed memory。这个改动让同一个知识库边界真正覆盖多智能体请求。

## 改动内容

- `OrchestrationRunner` / `run_orchestration` 接受可选 `SemanticMemoryStore` 和 scope；
- `orchestrate` 新增 `--memory-store`、`--memory-scope` 和
  `--context-memory versioned-v1+semantic`；
- planner、solver（含 speculative lanes）、reviewer 都通过同一个 `ContextCompiler` 做
  有界候选投影，同时保持角色历史隔离；
- role request 在进程停止后恢复时重放 receipt 中的原候选快照，不会静默换成 live store
  的新检索结果；
- 增加三角色投影和 solver pending replay 集成测试，并补充中英文文档。

## 不能从结果推出什么

当前 store 仍是 lexical、advisory notebook。测试证明的是候选投影、预算、provenance 和
重放协议，不证明 provider 理解/使用了记忆，也不证明代码成功率提升。
