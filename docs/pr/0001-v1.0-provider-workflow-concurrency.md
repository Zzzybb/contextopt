# PR note: v1.0 provider workflow concurrency guard

## What changed

- Add a repository/ref-scoped GitHub Actions concurrency group to both manual provider workflows.
- Set `cancel-in-progress: false`, so an explicitly started evaluation waits for an existing run
  instead of cancelling a paid experiment midway or silently creating overlapping provider load.
- Lock the contract in the workflow tests and document the behavior in both languages.

## Why

Real-provider matrices are intentionally manual and may consume quota or money. Two browser clicks
or a retry after a slow UI can otherwise run the same experiment concurrently. Serializing runs
preserves the operator's checkpoint/ledger interpretation and makes the cost boundary visible.

## Validation

```text
python -m unittest tests.test_workflow_contract -v
python scripts/ci_checks.py
```

## Claim boundary

This is a scheduling and cost-safety guard for GitHub Actions. It does not cancel a provider
request, prove remote exactly-once execution, or establish model quality.
