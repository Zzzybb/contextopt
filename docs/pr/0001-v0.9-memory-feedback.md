# v0.9 follow-up — idempotent semantic-memory feedback

## Summary

This follow-up closes the retrieval loop without introducing an un-audited embedding service:
after using a memory, an Agent can record whether it was helpful, and later searches apply a
small transparent adjustment.

## Changes

- Add the append-only `memory.feedback` event and `MemoryFeedbackResult` aggregate.
- Add the permission-gated `memory_feedback` tool with `helpful` / `not_helpful` labels.
- Use the durable tool-call id as an idempotency key; a retry returns the same revision and does
  not double-count the vote, while reusing an id with different payload is rejected.
- Expose `feedback_signal` in search evidence and apply at most a `0.05` bounded score adjustment;
  memory text, provenance, scope, and invalidation semantics remain unchanged.
- Extend the provider-free retrieval artifact and both language guides with a feedback probe.

## Claim boundary

This is an auditable heuristic, not learned confidence calibration, semantic understanding, or
proof that a model gave a correct label. The fixed probe only proves event replay, retry
idempotency, and bounded ranking movement. A future learned retriever still needs held-out tasks
and an explicit ablation.
