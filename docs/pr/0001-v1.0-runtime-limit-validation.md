# v1.0 runtime limit validation

## What changed

`RunLimits` now validates finite positive wall/command timeouts and strict positive integer
turn, tool-call, output-token, and output-byte limits both when constructed directly and when
loaded from a checkpoint. Optional total-token limits reject booleans and non-positive values.

## Why

Long-running agents rely on limits as a safety and cost boundary. Python comparisons silently let
`NaN`, infinity, floats, or booleans through several direct-constructor paths, which could create
an unbounded or non-reproducible run. The limits object now fails closed before a runner starts.

## Validation

- `python -m unittest tests.test_runtime -v`
- `python scripts/ci_checks.py`
- `python -m unittest discover -s tests -v`

## Claim boundary

This validates local configuration and checkpoint data. It does not guarantee scheduler fairness,
provider billing, OS isolation, or exactly-once external effects.
