# v1.0 provider runtime validation

## What changed

The OpenAI-compatible adapter now rejects malformed runtime controls before creating a
transport: empty/non-string identities, non-finite or non-positive timeouts, boolean or
negative retry counts, and non-finite or negative temperatures fail closed with explicit
`ValueError`s.

## Why

The adapter is the boundary that turns operator configuration into provider requests. Letting
`NaN`, infinity, booleans, or empty identities cross that boundary produces provider-specific
failures, unstable manifests, or misleading retry behavior. Early validation keeps the request
ledger and model-matrix protocol fingerprint meaningful.

## Validation

- `python -m unittest tests.test_runtime_model -v`
- `python scripts/ci_checks.py`
- `python -m unittest discover -s tests -v`

## Claim boundary

This is local configuration validation. It does not validate provider availability, pricing,
remote cancellation, model quality, or production security.
