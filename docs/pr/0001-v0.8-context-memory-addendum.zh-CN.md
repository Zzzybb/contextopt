# v0.8 角色上下文与观察记忆补充说明

## 本次范围

这是 PR #1 在代码 Agent 策略评测之后的后续变更说明：

- `OrchestrationConfig` 现在携带可序列化的 `ContextCompilerConfig`，默认使用有预算的
  submodular 策略和 `versioned-v1` 观察记忆；
- planner、solver、reviewer 分别保留自己的 assistant 历史，把历史和下一轮必选的
  system/user 请求一起编译后再调用模型；
- `RoleCall`、角色事件、checkpoint 以及 console/Markdown/HTML 报告都会暴露
  `ContextReceipt`、编译消息哈希、memory fingerprint 和 workspace generation；
- CLI 可以配置 policy、预算、recent block、工具输出上限和 memory policy，离线脚本与
  OpenAI-compatible 角色运行都能使用；
- checkpoint 解析兼容没有 role history/context receipt 字段的 v0.7 报告。

## 验证证据

编排测试验证所有完成的角色调用都有 receipt，下一轮请求确实收到 assistant 历史，观察
记忆指纹存在，并且 checkpoint round-trip 会保留历史和 receipt。全量测试还覆盖原有事件、
恢复、proposal 和评测契约。

~~~text
python -m unittest discover -s tests -q
python scripts/ci_checks.py
git diff --check
~~~

## 边界

这证明长上下文选择和基于 transcript 的观察记忆已经成为多 Agent 运行时中真实、有预算、
可审计的协议步骤；它不证明模型理解了被选中的历史，不代表已经有跨运行学习型记忆，也不
把固定 fixture 评测包装成生产级代码能力基准。
