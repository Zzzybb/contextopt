# v0.8 coding-agent strategy evaluation addendum

## What changed

This addendum records the v0.8 evaluation layer added to PR #1:

- `contextopt.evaluation.agent_search` defines two executable coding fixtures:
  an ACM-style Two Sum repair and an extended Euclidean algorithm repair;
- `agent-eval` compares `single_pass`, `best_of_n`, and `orchestrated` under paired
  round/model/candidate/test budgets;
- JSON and Markdown renderers expose the complete run ledger and self-consistent summaries;
- tests cover fixture completeness, visible-oracle signal, report round trips, tampering,
  configuration validation, and the offline CLI path.

The implementation deliberately uses `ScriptedModel` responses. The visible test command
is still a real process in a disposable temporary workspace, so candidate accounting and
oracle gates are exercised without requiring an API key.

## Why

The role orchestrator proved that planner/solver/reviewer state can be durable, but a role
transcript alone does not demonstrate value. This harness puts three recognizable coding-
Agent control policies on the same small algorithm/math tasks and records what each policy
actually spends. It gives an interview-ready explanation of why Best-of-N and retry loops
cost more calls/tests, and provides a stable seam for later real-model adapters.

## Reproduce

```text
python -m contextopt agent-eval \
  --fixtures all --repetitions 1 \
  --output agent-eval.json --markdown agent-eval.md

python -m unittest tests.test_agent_search_eval -v
```

The default offline matrix currently reports 0/2 for the deliberately weak `single_pass`
baseline, 2/2 for `best_of_n`, and 2/2 for `orchestrated`. The exact accounting is stored
in the generated JSON; the Markdown file is intended for a PR or portfolio artifact.

## Metrics and claim boundary

The primary metrics are visible-test `success_rate`, mean model/role calls, candidate
proposals, actual test processes, cached test reuses, rounds, and provider-reported token
usage. The ledger preserves failed runs. A completed command exits zero even when a weak
baseline fails, because that failure is an evaluation observation.

These are deterministic control-policy and protocol measurements with scripted responses.
They do not measure general model capability, hidden-test correctness, latency, provider
reliability, security isolation, or production coding success. A passing fixture is not a
claim that a real provider would discover the same algorithm.
