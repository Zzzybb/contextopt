# PR note: v1.0 provider transcript matrix replay

## Why

The single-run and multi-agent CLI cassettes made one trajectory reproducible, but the
real `agent-eval` matrix still had no durable provider boundary. A long run could produce
an output ledger while losing the exact planner/solver/reviewer calls needed to explain or
replay a cell offline.

## What changed

- `build_openai_model_factory` accepts `record_transcript_dir` and
  `replay_transcript_dir`.
- The factory passes the matrix repetition into a backward-compatible factory seam and
  stores one strict cassette at
  `{fixture}/{strategy}/repetition-{n}/{role}.jsonl`.
- `agent-eval --record-transcript-dir DIR` records real provider responses, while
  `agent-eval --replay-transcript-dir DIR` runs without provider credentials and fails
  closed on missing or changed request hashes.
- Replay reports use a distinct claim boundary: they reproduce a recorded provider
  trajectory, but they are not a fresh provider benchmark.
- The manifest records transcript mode, directory, and layout without API credentials.
- Tests cover two repetitions, per-cell file layout, CLI round-trip, and the fact that
  replay does not contact the local provider.

## Validation

```text
python -m unittest discover -s tests
python scripts/ci_checks.py
```

The real-provider workflow remains manual. The cassette is evidence for prompt/context
and long-horizon debugging; it does not provide an exactly-once guarantee for the remote
provider.
