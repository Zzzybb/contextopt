# v0.8 有界并行调度器补充说明

## 本次范围

这次后续变更加入第一个可执行的多 Agent 调度基础，同时保留原有 oracle 边界：

- `SearchSessionConfig.max_parallel_tests` 和 `OrchestrationConfig.max_parallel_tests`
  限制并发候选测试数；
- 每个候选继续由现有 executor 在独立临时工作区中执行，候选之间不共享文件，也不会
  修改模型可见的根快照；
- scheduler 按稳定的候选顺序记录 requested/completed 事件；
- session 和 orchestration 在每个候选完成后持久化 observation，并记录
  `max_in_flight`；恢复时复用已经落盘的结果，只重新执行尚未落账的候选；
- CLI 以及 Markdown/console 报告暴露配置并发数和实际最大并发数。

## 验证证据

新增 session 和 orchestration 测试使用四个独立候选、两 worker，断言实际最大并发为 2，
验证 4 个 requested/completed 事件，并比较最终 checkpoint 与内存报告。原有串行测试继续
使用 `max_parallel_tests=1` 作为确定性基线。

~~~text
python -m unittest tests.test_search_session tests.test_orchestrator -v
python -m unittest discover -s tests -q
python scripts/ci_checks.py
~~~

## 边界

这只是有界的并行 oracle 执行，不是自适应 PatchTree/MCTS、投机式模型调用、支持合并冲突
的工作区，也不是 OS sandbox。候选测试进程仍是受信任的宿主机代码。完成事件提供的是
至少一次的恢复语义：如果子进程结束后、checkpoint 原子替换前机器退出，该候选可能被重跑。
