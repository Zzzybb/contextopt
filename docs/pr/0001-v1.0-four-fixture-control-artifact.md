# PR #1 — v1.0 four-fixture control artifact and adapter smoke

## What changed

- Checked in a reproducible `3`-repetition control ledger for all four ACM/math fixtures under
  `experiments/v1.0-acm-math-4-fixtures/`.
- Updated the manual real-provider workflow input description to list the complete fixture
  registry (`two-sum`, `extended-gcd`, `merge-intervals`, `modular-inverse`).

  keeping the same request-shape, authorization, idempotency-key, visible-oracle, and hidden-
  grader assertions.
- Added English and Chinese experiment notes; the generated JSON/Markdown/HTML/checkpoint/
  manifest files are the exact baseline to compare against after an authorized provider run.

The control artifact contains `36` cells: `single_pass` accepts `0/12`, while `best_of_n` and
`orchestrated` each accept `12/12` visible cells and pass `12/12` independent hidden graders.

## Claim boundary

The control ledger remains a deterministic scripted baseline, and the local HTTP server is only
a protocol fixture. Neither establishes real-model coding ability, provider reliability,
multi-agent causal value, or production safety. A real comparison still requires a fixed provider,
model, prompt, budget, and at least three authorized repetitions.
