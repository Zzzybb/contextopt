# PR #1 — v1.0 Level 4 robustness evaluation

## What changed

- Added the provider-free `robustness-eval` CLI and a strict JSON/Markdown/HTML report model.
- Converted four previously scattered runtime contracts into an executable ledger:
  deterministic tool-output compaction, source-aware semantic-memory invalidation across a
  reopen, duplicate tool-result rejection, and stale compare-and-swap write refusal.
- Added a protocol manifest and a checked-in artifact under
  `experiments/v1.0-robustness-matrix/`.
- Added tests for the default matrix, report round trips/tamper detection, CLI artifacts, and
  scenario configuration; documentation is bilingual.

## Validation

```text
python -m unittest tests.test_robustness_eval -v
python -m contextopt robustness-eval --scenarios all ...
```

The fixed matrix passes `4/4` scenarios. Observed evidence includes the compacted block and
token bound, persisted invalidated memory status, the duplicate-result protocol error, and the
`content_conflict` CAS error with an unchanged workspace.

## Claim boundary

This is local runtime-contract evidence with no model calls or external network. It does not
establish machine-loss recovery, provider reliability, sandbox security, exactly-once effects,
or coding quality. The Level 3 real-provider matrix remains a separate authorized experiment.
