# v0.9 后续 — 基于 source_refs 的语义记忆自动失效

## 摘要

本次补齐一个长程运行的正确性缺口：持久化记忆可以引用工作区文件，但代码发生变更后，
旧记忆不能继续被静默召回。

## 改动

- 新增 `SemanticMemoryStore.invalidate_source_refs`：对 slash/case 归一化后精确匹配的
  `source_refs` 追加普通的 `memory.invalidated` 事件；只处理仍为 active 的条目。
- 成功执行 `create_file`、`replace_text` 后触发失效；如果进程在文件写入后、记忆账本更新前
  停止，write reconciliation 看到 postcondition 时会补做同一个失效动作。
- 成功写入的 tool metadata 暴露被失效的 memory id 和新 revision；记忆账本的 advisory
  故障不会把已经完成的工作区写入伪装成可重试的失败。
- 增加跨进程 replay、工具级测试，并补充中英文 runtime、evaluation、README 说明。

## 结论边界

这是一层 freshness protection，不是语义理解。它只处理精确的 source reference，不推断依赖，
不检测非文件世界变化，不自动 consolidation，也不证明模型一定会使用正确记忆。非文件原因
导致的过期仍需显式调用 `memory_invalidate`。
