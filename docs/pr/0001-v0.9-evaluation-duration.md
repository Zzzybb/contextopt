# PR note: v0.9 agent-evaluation wall-clock accounting

## Why

The evaluator already counted model, candidate, and oracle work, but it did not preserve a
per-cell runtime signal. Without that signal, a controlled policy comparison could discuss
cost and success while losing the local time trade-off that matters for a long-running coding
agent.

## What changed

- Record monotonic local wall-clock `duration_ms` for every fixture/strategy/repetition cell.
- Aggregate `mean_duration_ms` per strategy and add paired mean/observed-population-standard-
  deviation duration deltas to the comparison report.
- Render duration in console, Markdown, and HTML summaries and in the run ledger.
- Keep checkpoint/report loading backward-compatible: old reports without duration fields use
  the explicit zero default, while resumed runs compare deterministic fields independently of
  rerun timing.
- Update the English and Chinese README/evaluation wording and this bilingual PR note.

## Claim boundary

`duration_ms` measures local harness wall-clock time around one evaluation cell. It includes
local orchestration and, for a real provider, whatever network/provider time the adapter waits
for; it is not a provider latency SLA, a throughput benchmark, or evidence of model quality.
The fixed scripted matrix remains a protocol/control-policy conformance artifact.
