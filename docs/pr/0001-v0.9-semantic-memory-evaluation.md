# v0.9 follow-up — semantic-memory retrieval evaluation

## Summary

This follow-up turns the durable semantic-memory plumbing into a reproducible evaluation
artifact. It keeps retrieval behavior measurable without pretending a fixed lexical fixture is
model intelligence.

## Changes

- Add `contextopt memory-eval`, a provider-free fixed fixture with global/project scopes, tags,
  positive queries, negative queries, and an explicitly invalidated stale entry.
- Report hit@1, hit@k, mean reciprocal rank, negative-query pass rate, scope-isolation rate,
  invalidated-entry exclusion, repeated-search determinism, matched terms, scores, and raw
  memory ids in JSON, Markdown, and a self-contained HTML dashboard.
- Exercise one idempotent `helpful` feedback event so the artifact proves a bounded ranking
  adjustment without treating feedback as learned confidence.
- Add unit and CLI artifact tests; check in the regenerated report under
  `experiments/v0.9-semantic-memory`.
- Document the metric definitions and claim boundary in both READMEs and runtime/evaluation
  guides.

## Claim boundary

The evaluator makes zero model calls and uses the same deterministic lexical scorer as the
runtime store. A perfect fixed-fixture score demonstrates persistence, filtering, invalidation,
and reproducible ranking only. It does not establish embedding quality, semantic understanding,
whether an Agent chooses useful memories, or coding-task success. A future learned retriever
must use held-out tasks and an explicit ablation against this baseline.
