# v0.9 PR addendum: long-horizon recovery fault-injection matrix

## What changed

- Added the `recovery-eval` CLI command and a deterministic five-scenario matrix over the
  runtime's durable boundaries: pending model request, durable model response, reconciled write,
  durable write result, and non-replayable test execution.
- Each injected stop bypasses normal terminal handling after the selected event. Recovery opens
  the same event log with a fresh `AgentRunner`, `ScriptedModel`, and `WorkspaceTools` instance.
- Reports preserve pending-state reconstruction, event sequences before/after resume, model-call
  counts, tool-event counts, final fixture digest, and an explicit claim boundary in JSON,
  Markdown, and a self-contained HTML dashboard.
- Added a protocol manifest, bilingual experiment notes, and a bilingual PR change note.

## Verification

```text
python -m contextopt recovery-eval \
  --output experiments/v0.9-recovery-matrix/report.json \
  --markdown experiments/v0.9-recovery-matrix/report.md \
  --html experiments/v0.9-recovery-matrix/report.html \
  --manifest experiments/v0.9-recovery-matrix/manifest.json

python -m unittest tests.test_recovery_eval -v
python scripts/ci_checks.py
```

The matrix passes `5/5` scenarios. The non-replayable `run_tests` case intentionally records a
first `paused` resume and only completes after an explicit `mark_failed` resolution. The durable
final-response case resumes with zero additional model calls; both write cases record exactly one
completed write event.

## Boundary

The matrix proves the covered local recovery state machine and accounting protocol. It does not
prove recovery from arbitrary machine loss, malicious workspace/log replacement, exactly-once
provider effects, OS sandbox security, or real-model coding quality. The model is deterministic
`ScriptedModel`; a real provider benchmark remains a separate, explicitly versioned evaluation.
