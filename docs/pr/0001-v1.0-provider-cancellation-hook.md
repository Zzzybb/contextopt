# PR note: v1.0 provider cancellation hook

## Why

The speculative solver already records a winner and asks unfinished lanes to stop, but the
generic OpenAI-compatible adapter previously had no way to notify a provider-specific remote
abort API. That made `acknowledged` mean only that the local HTTP response was closed.

## What changed

- Add an optional `cancellation_url` to `OpenAICompatibleModel` and the `--cancellation-url`
  flags used by `run`, `resume`, `search-session`, `propose-case`, `orchestrate`, and `agent-eval`.
- After setting the local cancellation event and closing the active response, POST
  `{"request_idempotency_key": "...", "model": "..."}` to the configured endpoint.
- Reuse the configured authorization and idempotency headers; map 2xx to `acknowledged`, 404/405
  to `unsupported`, and other HTTP/network failures to `failed:*`.
- Persist the endpoint in the non-secret adapter configuration so resume rejects a changed
  cancellation contract, while manifests strip query strings and fragments.
- Add provider-free success/unsupported endpoint tests and keep the local transport regression.

## Validation


## Claim boundary

The endpoint is an explicit provider integration contract, not a Chat Completions standard. A
2xx response means the configured endpoint accepted the abort request; it does not independently
prove that server-side generation stopped or that remote billing was avoided. No real provider
was contacted by the tests.
