# v1.0 sandbox 隔离策略

## 改了什么

新增双语候选代码执行隔离策略，区分受信宿主机运行、有界的可选 Docker 路径，以及不受信生成代码需要的
外部 VM 边界；同时增加契约测试，锁定 Docker 命令的网络、capability、权限、文件系统、资源和临时目录参数。

## 为什么改

“启用 Docker”不等于“安全 sandbox”。代码 Agent benchmark 在比较结果前，需要明确 kernel、网络、挂载、
凭据和资源限制的范围。策略让边界可审查，并把仍需完成的 VM 工作写清楚，而不是默默夸大 container 隔离。

## 如何验证

- `python -m unittest tests.test_branch_executor -v`
- `python scripts/ci_checks.py`
- GitHub Actions Docker candidate smoke

## Claim boundary

策略和 Docker 契约测试不会配置或认证 VM、Docker daemon、侧信道隔离或 provider 侧取消。它们是可复现的
本地/CI 边界和未来受控真实模型运行的操作者检查清单。
