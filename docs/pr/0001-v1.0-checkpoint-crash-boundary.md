# PR note: v1.0 atomic checkpoint interruption boundary

## What changed

- Add a fault-injection test that interrupts `write_projection_checkpoint` at the atomic
  `os.replace` boundary.
- Verify that the previous checkpoint remains loadable against its event prefix and that the
  temporary file is removed after the failed replacement.
- Record the evidence and claim boundary in English and Chinese.

## Why

Long-running agents must survive a process or machine stop while persisting recovery state. A
round-trip test proves serialization, but not what happens when the final rename fails. The test
locks the intended atomic-write contract without claiming durable hardware guarantees.

## Validation

```text
python -m unittest tests.test_runtime_recovery -v
python scripts/ci_checks.py
```

## Claim boundary

This is a local simulated replacement failure. It proves preservation of the last complete cache
under that injected failure and cleanup of the temporary file; it is not a filesystem durability,
power-loss, distributed storage, or exactly-once external-effect guarantee.
