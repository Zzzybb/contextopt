# v0.8 评测结果面板补充说明

## 本次范围

这次后续变更为代码 Agent 评测增加可审查的可视化出口，不改变评测协议和已有的结论边界：

- `render_agent_evaluation_html(report)` 从与 console、Markdown 相同的 `AgentEvalReport`
  生成无依赖、自包含的 HTML dashboard；
- 面板展示 visible 成功率、条件式 hidden 成功率、策略级成本指标
  （`mean_model_calls`、`mean_test_calls`、`mean_total_tokens`），并在结果旁保留 claim
  boundary；
- 完整的可序列化报告会放进可折叠 JSON ledger，审阅者可以查看 fixture、策略和 repetition
  的原始记录，而不必只相信图表；
- `agent-eval --html PATH` 可以和已有 JSON、Markdown 一起写出面板；不传该参数时，之前的
  CLI 行为不变；
- README、runtime/evaluation 文档以及这份中英文 PR 说明都记录了作品集/PR 用法，并明确
  真实模型运行仍属于探索性实验。

## 为什么做

评测已经记录了适合 Agent 工程面试讨论的 accounting，但原始 JSON 不容易看出质量与成本的
关系。静态 HTML 让同一份运行结果可以直接在浏览器或 PR 中审阅，同时保留 JSON ledger 作为
事实来源。实现没有外部 JavaScript/CSS 依赖、网络请求，也没有新增评分规则。

## 验证证据

renderer 测试覆盖 visible/hidden 图例、策略表、claim boundary 和嵌入式持久化 payload；CLI
测试通过公开命令同时写出三种格式：

~~~text
python -m unittest tests.test_agent_search_eval -v
python -m ruff check src tests
python -m mypy src/contextopt
python -m unittest discover -s tests -q
python scripts/ci_checks.py
~~~

## 边界

面板只是展示层，不会提高模型质量、隐藏失败的 baseline，也不会把确定性 fixture 变成泛化、
延迟、provider 稳定性或生产安全的证据。hidden 成功率仍以 visible 通过为前提；真实 provider
的重复实验仍需固定模型/版本、prompt、fixture、工具和预算后才能进行比较。
