# PR #1 — v0.9 OpenAI-compatible provider 本地 smoke

## 为什么做

真实 provider benchmark 必须保持手动触发、不能让 CI 泄露 secret；但 adapter 到
`agent-eval` 的实际边界仍应该自动验证。现在用本地 HTTP fixture 走完整的
OpenAI-compatible 请求路径，返回一个完整候选并经过 visible/hidden oracle。

## 改动内容

- 在 agent evaluation 测试中加入本地 Chat Completions 兼容服务器；
- 通过真实 `OpenAICompatibleModel` 和 `run_agent_evaluation` 跑 ACM two-sum fixture；
- 校验 endpoint、Bearer authorization、稳定 idempotency header、model 名称及候选通过；
- CI 不访问外网、不需要 provider 账号或 secret。

## 不能从结果推出什么

这是 adapter/harness 协议 smoke，不是模型质量证据。响应由本地确定性 fixture 生成。
真实 provider 矩阵仍需手动提供 `CONTEXTOPT_API_KEY`。
