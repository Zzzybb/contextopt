# PR note: v0.9 manual real-provider evaluation workflow

## Why

The deterministic ACM/math artifact proves protocol and accounting behavior, but it must not be
presented as model quality. A reproducible path is needed for an operator with a provider key to
run the same fixed matrix against a real OpenAI-compatible endpoint.

## What changed

- Added a manual-only `real-agent-eval` GitHub Actions workflow.
- The workflow accepts model, endpoint, fixture, strategy, and repetition inputs; it requires the
  `CONTEXTOPT_API_KEY` secret and never prints it.
- It uploads the JSON ledger, Markdown report, self-contained HTML dashboard, manifest, and
  checkpoint as one run artifact.
- Added English and Chinese instructions and the same small-sample claim boundary used by the
  evaluator.

## Claim boundary

The workflow is an operator-controlled exploratory benchmark. It does not claim general model
capability, statistical power, provider reliability, latency guarantees, exactly-once billing,
or production safety. Keep model, prompts, fixtures, tools, limits, and repetitions fixed when
comparing runs.
