# PR note: v0.9 local HTTP transport cancellation

## Why

The speculative solver already requested provider cancellation before cancelling local asyncio
tasks, but the built-in standard-library adapter returned `unsupported` for every request. That
left a real active HTTP read running in a worker thread even when the local scheduler had a
valid winner.

## What changed

- Track each active OpenAI-compatible request by its stable idempotency key.
- Expose a thread-safe cancellation event and close an active local `urllib` response when the
  speculative orchestrator asks for cancellation.
- Convert the interrupted worker into a non-retryable `ModelError(code="cancelled")`, so it
  cannot silently retry after a winner.
- Keep the cancellation registry alive when an outer asyncio task is cancelled; cleanup runs
  only after the shielded worker thread exits, so a late operator/orchestrator signal can still
  close the transport.
- Have the runtime `AgentRunner` invoke the same optional hook on model wall-timeout or outer
  task cancellation, instead of relying only on speculative solver orchestration.
- Make retry backoff wait on the cancellation event, so a cancelled 429/5xx retry does not sleep
  through the operator's cancellation signal.
- Report `acknowledged`, `not_observed`, `unsupported`, or `failed:*` in the existing cancellation
  ledger and add a blocking transport regression test.
- Keep the claim boundary explicit: closing the client transport is not a provider-side abort
  guarantee, and configured model/candidate budgets still charge the speculative width.

## Validation

```text
python -m unittest tests.test_runtime_model -v
python -m unittest discover -s tests -q
python scripts/ci_checks.py
```

## Claim boundary

`acknowledged` means that the local adapter accepted the cancellation signal and closed an active
HTTP response. It does not establish that a generic provider stopped server-side generation or
that remote billing was avoided.
