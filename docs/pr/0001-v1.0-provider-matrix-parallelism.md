# PR note: v1.0 bounded provider matrix parallelism

## What changed

- Cap the model-cell fan-out in `real-agent-model-matrix.yml` at two concurrent provider jobs.
- Keep the existing repository/ref concurrency group, so separate workflow runs wait and each run
  also limits its own provider pressure.
- Lock the cap in the workflow contract test and document the operational boundary bilingually.

## Why

Multi-model evaluation is itself a bounded orchestration problem. Launching every supplied model at
once can trigger rate limits, hide per-cell failures behind provider overload, and create an
uncontrolled cost spike. A small explicit cap preserves parallelism while keeping the experiment
auditable and repeatable.

## Validation

```text
python -m unittest tests.test_workflow_contract -v
python scripts/ci_checks.py
```

## Claim boundary

`max-parallel: 2` is a GitHub Actions scheduling limit, not a provider throughput guarantee. It
does not prove latency, reliability, cancellation, or model quality.
