# PR #1 — v0.9 自动语义上下文候选评测

## 为什么加这一层

`versioned-v1+semantic` 已经能在模型请求前检索 durable memory 候选，但必须把
“运行时协议正确”与“模型能力提升”分开。这个评测完全离线，只验证候选是否被检索、
是否在同一 token 预算下被淘汰，以及收据能否在没有 live store 时重放。

## 改动内容

- 新增 `contextopt semantic-context-eval`，使用固定 ACM/数学记忆和任务 fixture；
- 对 `recent`、`topk`、`density`、`submodular` 以及多个确定性预算做矩阵运行；
- 记录 retrieved/selected id、fixture-label recall、候选 token、淘汰数、预算合规、
  receipt 确定性和无 store 重放；
- 新增 JSON、Markdown、自包含 HTML 渲染器及单元/CLI 测试；
- CI 增加 smoke 命令，并提交 `experiments/v0.9-semantic-context/` 中英文产物。

## 不能从结果推出什么

评测始终 `model_calls=0`。recall 只是固定 fixture 的 memory id 是否保留，不代表
embedding 质量、语义理解、模型实际使用了记忆，也不代表代码 patch 成功率提升。
真实 provider 的多轮矩阵仍需单独、明确授权的 key。

## 验证命令

```text
python -m contextopt semantic-context-eval --repetitions 2 --budgets 128,512
python -m unittest tests.test_semantic_context_eval -v
```
