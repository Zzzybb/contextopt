# PR 说明：v1.0 provider 评测矩阵轨迹重放

## 为什么做

之前的单 Agent 和多智能体 CLI cassette 可以复现一条轨迹，但真实 `agent-eval` 矩阵
仍然没有持久化 provider 边界。长时间运行虽然能产出结果 ledger，却无法保留解释某个
fixture/策略单元所需的完整 planner/solver/reviewer 请求，断网后也无法重放。

## 改动内容

- `build_openai_model_factory` 新增 `record_transcript_dir` 和
  `replay_transcript_dir`。
- 工厂把 repetition 传入兼容旧工厂签名的 seam，并按
  `{fixture}/{strategy}/repetition-{n}/{role}.jsonl` 保存严格 cassette。
- `agent-eval --record-transcript-dir DIR` 记录真实 provider 响应；
  `agent-eval --replay-transcript-dir DIR` 不需要 provider 凭据，遇到请求缺失或 hash
  变化会 fail closed。
- 重放报告使用独立的 claim boundary：它复现已记录的 provider 轨迹，但不是新的真实
  provider benchmark。
- manifest 记录 cassette 模式、目录和布局，不记录 API key。
- 测试覆盖两次 repetition、按单元的文件布局、CLI round-trip，以及重放不会访问本地
  provider。

## 验证

```text
python -m unittest discover -s tests
python scripts/ci_checks.py
```

真实 provider workflow 仍然只手动运行。cassette 适合 prompt/context 和长程运行调试，
但不对远端 provider 做 exactly-once 保证。
