# PR note: v1.0 provider-free model-matrix demo

## What changed

- Add `scripts/run_model_matrix_demo.py`, which generates two deterministic four-fixture,
  three-repetition bundles and feeds them through `agent-eval-compare`.
- Add bilingual usage notes under `examples/model_matrix_demo/` with the generated artifact map and
  an explicit control-replica claim boundary.
- Extend `scripts/ci_checks.py` to lint and format-check the repository's scripts, fixing the
  pre-existing import/line-wrap violations exposed by that broader gate.
- Render absent scripted provider identities as `n/a` instead of the Python string `None`, so a
  control replica cannot be mistaken for a real model name in the portfolio report.

## Why

The real-provider workflow correctly requires an API key, but an interviewer or contributor should
still be able to see the full collection-to-analysis path immediately. This demo exercises the
same manifest matching, protocol fingerprint, paired comparison, and JSON/Markdown/HTML renderers
without network access or pretending that scripted controls are model evidence.

## Validation

```text
python scripts/run_model_matrix_demo.py --output-dir build/model-matrix-demo
python -m unittest tests.test_model_matrix
python -m unittest tests.test_model_matrix_demo
python scripts/ci_checks.py
```

## Claim boundary

The two labels are deterministic control replicas, not independent real models. The generated
matrix proves plumbing and accounting only; it does not establish model quality, generalization,
provider behavior, or production safety.
