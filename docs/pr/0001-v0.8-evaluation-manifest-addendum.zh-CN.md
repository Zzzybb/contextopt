# v0.8 评测 manifest 补充说明

## 本次范围

`agent-eval --manifest PATH` 现在会在矩阵开始前写出可复现实验 sidecar：

- 记录 adapter、模型名、去掉 query/fragment 的 endpoint、temperature、timeout、重试次数、
  API-key 环境变量名、完整评测配置，以及来自 `CONTEXTOPT_GIT_REVISION` 或 `GITHUB_SHA` 的
  可选 repository revision；
- 它与持久化结果 schema、checkpoint ledger 分开；
- 只记录环境变量名，不会序列化 API key 值；
- CLI 测试覆盖 manifest 与 JSON、Markdown、HTML、checkpoint 一起生成。

## 为什么做

如果结果 ledger 没有模型和运行时身份，就很难复现或审计。sidecar 让固定 provider 的
比较可以被审阅，同时把 credential 排除在 artifact 外，也能让恢复中的矩阵明确绑定到
创建 checkpoint 时的同一配置。

## 验证证据

~~~text
python -m unittest tests.test_agent_search_eval -v
python -m ruff check src tests
python -m mypy src/contextopt
python -m unittest discover -s tests -q
python scripts/ci_checks.py
~~~

## 边界

manifest 记录身份，不保证 provider 确定性、exactly-once 调用、统计功效或模型质量。
endpoint 的 query 和 fragment 会移除，但仍不应把 credential 放进 base URL。
