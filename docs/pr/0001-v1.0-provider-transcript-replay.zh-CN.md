# PR #1 — v1.0 provider 轨迹录制与离线重放

## 改动

- 增加严格的 `ModelRequest.to_dict()` / `from_dict()` 序列化，让标准化 provider 输入可以
  独立审计和匹配，不依赖某个 SDK。
- 增加 `ModelTranscript`、`RecordingModel`、`ReplayModel`：可选的 JSONL cassette。它会在
  成功响应后 `fsync` 请求/响应，不保存 API key，校验连续 sequence、响应/记录 hash chain，
  并拒绝被篡改的记录。
- 重放必须匹配完整 request hash，并支持长程恢复使用的 durable-call cursor；请求不匹配或
  cassette 耗尽时会用稳定的 `ModelError` code fail closed。
- 通过 `run`、`search-session`、`propose-case` 和 `resume` 暴露
  `--record-transcript` / `--replay-transcript`，因此离线复现不需要额外 Python glue 或
  provider credential。
- 为 `orchestrate` 增加按角色的目录 cassette：一次录制分别写入 planner、solver、reviewer，
  重放时如果 visible-test 观察改变会拒绝，而不是静默使用过期 reviewer 结果。
- 在 runtime、architecture 文档和本双语 PR 说明中记录使用方式与边界。

## 验证

```text
python -m unittest tests.test_runtime_transcript -v
python -m unittest tests.test_runtime_cli.RuntimeCliTests.test_run_can_record_then_replay_provider_transcript
python -m unittest tests.test_orchestrator.OrchestratorTests.test_cli_orchestrate_records_and_replays_role_transcripts
python -m ruff check src tests
python -m ruff format --check src tests
python -m mypy src/contextopt
```

无需 provider 的测试覆盖录制/重放 round-trip、cursor resume、请求不匹配和篡改拒绝。
该 cassette 只用于观察和调试，不能冒充远端 exactly-once。

## 边界

录制只能证明 wrapper 返回后标准化响应已经在本地持久化；重放只能证明相同请求序列的协议
可复现，不能证明模型能力、provider 稳定性、延迟、成本或多智能体收益。
