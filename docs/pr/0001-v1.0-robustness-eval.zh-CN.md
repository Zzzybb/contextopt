# PR #1 — v1.0 Level 4 运行时鲁棒性评测

## 改动

- 增加无需 provider 的 `robustness-eval` CLI，以及严格的 JSON/Markdown/HTML 报告模型。
- 将四个原本分散的运行时 contract 转成可执行 ledger：确定性的 tool output 压缩、
  source-aware 语义记忆重开后的失效、重复 tool result 拒绝、陈旧 compare-and-swap 写入
  拒绝。
- 增加 protocol manifest，并在 `experiments/v1.0-robustness-matrix/` 提交固定 artifact；
  manifest 固定源码 revision `330e047a3170a799fc4c434a94b2178f33d6791a`。
- 增加默认矩阵、报告 round-trip/tamper、CLI artifact 和场景配置测试，文档中英文成对。

## 验证

```text
python -m unittest tests.test_robustness_eval -v
python -m contextopt robustness-eval --scenarios all ...
```

固定矩阵 `4/4` 个场景通过。观察证据包括压缩 block 与 token 上限、重开后记忆的
`invalidated` 状态、重复结果协议错误、`content_conflict` CAS 错误以及未改变的 workspace。

## 边界

这是无需模型调用、无需外部网络的本地 runtime contract 证据，不能证明机器掉电恢复、
provider 稳定性、sandbox 安全、exactly-once 副作用或代码能力。Level 3 真实 provider 矩阵
仍是需要授权的独立实验。
