# PR 说明：v1.0 workspace 知识库索引

## 为什么做

semantic-memory 层已经可以持久化人工保存的 procedure 和 fact，但代码 Agent 仍没有一条
可复现的路径把仓库本身变成可搜索知识库。最相关的源码证据因此还在跨运行上下文管线之外。

## 改动内容

- 在 `contextopt.runtime.knowledge` 新增 `KnowledgeIndexConfig`、`KnowledgeIndexReport` 和
  `index_workspace`。
- 新增 `knowledge-index` CLI，并显式控制文件、字节数、后缀、目录和点文件边界。
- 每个分块带相对路径/行号 header、`source_refs`、`knowledge-chunk-v1` tag，并沿用现有
  append-only semantic-memory ledger 的内容 identity。
- 重新索引时复用不变分块；变更或删除的分块追加失效事件；重新打开 store 后检索视图保持一致。
- 新增可审计 JSON/Markdown 报告，记录文件数量、跳过原因、分块成本和快照 fingerprint。
- 新增中英文指南、PR 说明和测试，覆盖重复运行、source-aware 失效、边界、CLI 产物和跨进程
  reopen。

## Claim boundary

该索引是确定性的 lexical 源码投影，证明 provenance、新鲜度、有界检索和持久化；不声称
embedding 质量、自动总结、模型使用了每条检索结果，或代码成功率提升。
