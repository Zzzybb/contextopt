# v0.8 trace dashboard addendum

## Scope

This follow-up adds a read-only visual surface for the durable runtime event log:

- `render_trace_html` produces a dependency-free local HTML timeline from the same JSONL events
  consumed by `render_trace`;
- the dashboard summarizes event count, model requests, tool outcomes, and ContextReceipt count;
- every event keeps an expandable, escaped JSON payload so the visualization cannot replace the
  audit source;
- `contextopt trace EVENT_LOG --html PATH` writes the dashboard while preserving the compact
  trace on stdout;
- tests cover the CLI path and verify that context and model-request events are visible.

## Why

Long-horizon agent failures are easier to diagnose when context decisions, model calls, tool
observations, and recovery boundaries can be scanned on one timeline. This is a local rendering
layer only: it does not mutate the log, weaken hash-chain validation, or claim that a trace is
evidence of model quality.

## Claim boundary

The dashboard is a debugging and portfolio view over an existing event source. It is not an OS
sandbox, a remote observability service, a learned memory system, or a statistically powered
real-model benchmark.
