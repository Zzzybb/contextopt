# PR #1 — v0.9 终态语义记忆反馈闭环

## 改动

- 新增可选的 `OrchestrationConfig.memory_feedback`，以及对应的
  `orchestrate --memory-feedback` CLI 开关。
- 编排进入终态时，只收集 planner、solver、reviewer 的 ContextReceipt 中**实际被选中**的
  durable memory 候选。运行 accepted 时写入 `helpful`，exhausted/failed 时写入
  `not_helpful`。
- 使用 `run_id` 与 `memory_id` 生成确定性的 feedback key，并把 `memory.feedback` 事件追加到
  编排 hash chain。重开 terminal checkpoint 时会复用同一幂等操作，不会重复计票。
- 记忆在运行期间已经失效或不存在时，仍记录 `skipped` 审计事件，但不改变代码运行结果；
  console/Markdown 报告新增 `memory_feedback_events` 指标。

## 边界

这是供后续 lexical ranking 使用的、持久化且幂等的运行结果相关性信号，不证明某条记忆导致
补丁成功，不做自动记忆 consolidation，也不测量真实 provider 的代码能力。该能力显式 opt-in，
旧的非语义记忆运行不会受到影响。
