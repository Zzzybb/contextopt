# v0.9 follow-up — source-aware semantic-memory invalidation

## Summary

This follow-up closes a long-horizon correctness gap: durable memories can cite workspace
sources, but a later code edit must not leave those memories silently retrievable.

## Changes

- Add `SemanticMemoryStore.invalidate_source_refs`, which appends ordinary
  `memory.invalidated` events for active entries whose exact source reference matches the changed
  path after slash/case normalization.
- Call the boundary after successful `create_file` and `replace_text` mutations, and during
  write reconciliation when the postcondition proves that a prior process already changed the
  file.
- Expose invalidated memory ids and the new memory revision in successful write metadata without
  making advisory-ledger failures turn a completed workspace write into a retryable tool error.
- Add replay and tool-level tests, plus English/Chinese runtime, evaluation, and README guidance.

## Claim boundary

This is freshness protection, not semantic understanding. It only handles exact source-reference
matches and does not infer dependencies, detect non-file world changes, consolidate memories, or
prove that a model would have used the right memory. Non-file staleness still requires an explicit
`memory_invalidate` call.
