# PR #1 — v1.0 多智能体 provider adapter smoke

## 改动

- 增加确定性的本地 OpenAI-compatible HTTP fixture，返回编排器实际使用的 planner、solver、
  reviewer 严格 JSON contract。
- 对四个 ACM/数学 fixture 走完整真实 HTTP adapter 路径，使用不同的 planner/solver/reviewer
  模型名，并校验 authorization、endpoint 和 idempotency key。
- smoke 不访问真实 provider：只监听 loopback，不读取环境 API key；reviewer gate 接受后才
  运行独立 hidden grader。

## 验证

```text
python -m unittest tests.test_agent_search_eval.AgentEvaluationTests.test_real_adapter_orchestrated_matrix_path_works_with_local_provider
python -m unittest discover -s tests
python scripts/ci_checks.py
```

该 smoke 对四个 fixture 全部接受；每个 fixture 恰好产生一次 planner、一次 solver 和一次
reviewer 请求。每个请求都使用 `/v1/chat/completions`、配置的 authorization header、唯一的
`contextopt-*` idempotency key，以及对应角色模型。

## 边界

这是 adapter 与多智能体编排 contract 的 smoke，不是模型能力、provider 稳定性、延迟、成本或
多智能体因果收益证据。真实 provider 矩阵仍是需要手工授权的独立实验，必须固定模型、prompt、
预算并至少重复三次。
