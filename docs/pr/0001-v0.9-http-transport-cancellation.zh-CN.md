# PR 说明：v0.9 本地 HTTP 传输取消

## 为什么做

speculative solver 已经在取消本地 asyncio task 前请求 provider cancellation，但内置的
标准库 adapter 对所有请求都返回 `unsupported`。因此即使已有有效 winner，worker thread
里的活动 HTTP read 仍可能继续运行。

## 改动内容

- 使用稳定的幂等 key 跟踪每个活动的 OpenAI-compatible 请求；
- 增加线程安全的 cancellation event，在 speculative orchestrator 请求取消时关闭活动的
  本地 `urllib` response；
- 将被打断的 worker 转成不可重试的 `ModelError(code="cancelled")`，避免 winner 出现后
  静默重试；
- 如果外层 asyncio task 先被取消，仍保留 cancellation registry，直到 shielded worker
  thread 真正结束才清理，因此 orchestrator/operator 稍后仍能关闭 transport；
- runtime `AgentRunner` 在模型 wall-timeout 或外层 task cancellation 时也会调用同一个可选
  hook，不再只依赖 speculative solver 编排层；
- 在已有取消 ledger 中记录 `acknowledged`、`not_observed`、`unsupported` 或 `failed:*`，并增加阻塞传输
  回归测试；
- 保持结论边界：关闭客户端传输不等于 provider 远端 abort，配置的模型/候选预算仍按
  speculative width 记账。

## 验证命令

~~~text
python -m unittest tests.test_runtime_model -v
python -m unittest discover -s tests -q
python scripts/ci_checks.py
~~~

## 结论边界

`acknowledged` 表示本地 adapter 接收了取消信号并关闭活动 HTTP response；它不能证明
通用 provider 已停止服务端生成，也不能证明远端计费已经避免。
