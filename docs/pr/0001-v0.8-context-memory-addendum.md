# v0.8 role-context and observed-memory addendum

## Scope

This addendum documents the follow-up changes to PR #1 after the coding-agent strategy
evaluation layer:

- `OrchestrationConfig` now carries a serializable `ContextCompilerConfig` with a bounded
  submodular policy and `versioned-v1` observed-memory signals by default;
- planner, solver, and reviewer each retain only their prior assistant responses, compile that
  history together with the next mandatory system/user request, and call the provider with the
  compiled request;
- `RoleCall`, role events, checkpoints, and console/Markdown/HTML reports expose the resulting
  `ContextReceipt`, compiled-message hash, memory fingerprint, and workspace generation;
- CLI flags expose policy, budget, recent-block, tool-output, and memory settings for offline or
  OpenAI-compatible role runs;
- checkpoint parsing remains backward-compatible with v0.7 reports that have no role history or
  context receipt fields.

## Evidence

The orchestrator tests now verify that all completed role calls have receipts, subsequent rounds
receive assistant history, observed-memory fingerprints are present, and checkpoint round trips
preserve the histories and receipts. The full suite also covers the existing event, recovery,
proposal, and evaluation contracts.

```text
python -m unittest discover -s tests -q
python scripts/ci_checks.py
git diff --check
```

## Claim boundary

This proves that long-context selection and transcript-derived memory are real, bounded, and
auditable protocol steps in the multi-agent runtime. It does not prove that a model understood
the selected history, that observed memory is learned across runs, or that the deterministic
fixture matrix is a production coding benchmark.
