# v0.8 merge-aware snapshot addendum

## Scope

This follow-up adds an opt-in, evidence-first reconciliation step for independent solver
branches:

- `three_way_merge` compares each candidate snapshot with the same root snapshot;
- unchanged paths, identical edits, and edits made by only one side are merged safely;
- divergent same-path edits produce `MergeConflict` records with base/left/right fingerprints
  and no partial workspace;
- `OrchestrationConfig(merge_policy="disjoint")` appends bounded merged candidates before the
  visible oracle, consumes the shared candidate/test budgets, and records a `solver.merge` event;
- `--merge-policy {disabled,disjoint}` exposes the feature in the orchestration CLI;
- deterministic tests cover both conflict rejection and a passing disjoint merge.

## Why

Independent solver branches often touch different files. Testing only each branch throws away a
potentially compatible combination, while textually guessing through a same-path conflict is
unsafe. A three-way merge makes the compatibility decision explicit and lets the executable
oracle decide whether the combined snapshot works.

## Evidence

```text
python -m unittest tests.test_orchestrator -v
python -m ruff check src tests
python -m mypy src/contextopt
python -m unittest discover -s tests -q
python scripts/ci_checks.py
```

## Claim boundary

This is bounded merging of already returned complete snapshots. It does not perform concurrent
provider calls, resolve semantic conflicts, provide an OS sandbox, or establish multi-agent value
on real models. Every merged candidate still needs the same visible-test oracle and shared budget.
