# PR 说明：v1.0 按角色固定 model identity

## 为什么做

OpenAI-compatible factory 其实已经支持 planner、solver、reviewer 使用不同 model，但
`AgentEvalConfig` 之前没有持久化这些 identity。这样 resume 时可能悄悄切换某个角色的部署，
checkpoint 却仍然被认为兼容。

## 改动内容

- 在 agent-eval config 和 checkpoint fingerprint 中保存可选的 `planner_model`、`solver_model`、
  `reviewer_model`；
- provider manifest 也记录这些 identity，但不写入凭据；
- 手动 GitHub Actions workflow 和本地 CLI 暴露相同的可选覆盖参数；
- scripted/replay 默认保持向后兼容，未指定覆盖时继续使用 base model。

## 验证

```text
python scripts/ci_checks.py
python -m unittest tests.test_agent_search_eval
```

本地 provider fixture 已经校验按角色发送不同 model；新增 checkpoint round-trip 测试校验三个
identity 都能在序列化后保留。

## 结论边界

按角色路由 model 是实验控制与可复现性能力，不声称某种角色拆分一定提升真实模型代码质量。
