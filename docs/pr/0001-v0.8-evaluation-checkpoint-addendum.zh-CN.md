# v0.8 评测矩阵 checkpoint 补充说明

## 本次范围

这次后续变更让重复代码 Agent 评测可以跨 provider 或进程中断继续运行：

- `AgentEvalCheckpoint` 保存经过校验的矩阵配置、fixture id 和已经完成的
  fixture/strategy/repetition cell，不序列化隐藏 grader 源码；
- `write_agent_evaluation_checkpoint` 使用同目录临时文件、`fsync` 和原子替换；首次 cell
  前写入一次，之后每完成一个 cell 再更新；
- `run_agent_evaluation(..., checkpoint_path=..., resume=True)` 校验配置和 fixture 身份，
  复用已经持久化的 cell，只执行缺失的 observation；
- 公共 CLI 增加 `--checkpoint PATH` 和 `--resume`，已有 JSON/Markdown/HTML 报告仍只在矩阵
  完成后输出；
- 如果 provider 调用完成但进程在 checkpoint 替换前退出，该 cell 可能再次运行，因此这是
  at-least-once 恢复，不是 exactly-once provider 执行。

## 为什么做

真实模型重复实验是可信 Agent 比较中最昂贵的部分。进程级 checkpoint 可以避免最后一个
fixture 失败导致之前的 cell 全部丢失，并保留可审阅的完整 ledger。checkpoint 保存的是
accounting，不保存 credential 或隐藏 grader 源码；配置不一致时直接拒绝，避免悄悄混合实验。

## 验证证据

测试创建两 repetition 的矩阵，验证原子写入的 checkpoint，再把它替换成只含一个 cell 的
partial checkpoint，resume 后得到相同的自洽报告；公共 CLI 测试也会在 JSON、Markdown、HTML
旁边写出 checkpoint：

~~~text
python -m unittest tests.test_agent_search_eval -v
python -m ruff check src tests
python -m mypy src/contextopt
python -m unittest discover -s tests -q
python scripts/ci_checks.py
~~~

## 边界

这提升的是实验耐久性，不是 provider 幂等性、benchmark 统计功效或模型质量。若模型请求在
原子 cell 替换前已经完成，崩溃恢复后可能重跑。checkpoint 不会让宿主机测试命令变安全，也
不会把固定 ACM/数学 fixture 变成泛化、延迟、稳定性、安全隔离或生产安全的证据。
