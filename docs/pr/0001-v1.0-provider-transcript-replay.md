# PR #1 — v1.0 provider transcript recording and replay

## What changed

- Added strict `ModelRequest.to_dict()` / `from_dict()` serialization so normalized provider
  inputs can be audited and matched independently of an SDK.
- Added `ModelTranscript`, `RecordingModel`, and `ReplayModel`: an opt-in JSONL cassette that
  fsyncs successful request/response pairs, stores no API key, validates contiguous sequence
  numbers and a response/record hash chain, and rejects tampered records.
- Replay matches the complete request hash and supports the same durable-call cursor used by
  long-running recovery; mismatch and exhaustion fail closed with stable `ModelError` codes.
- Exposed the cassette through `run`, `search-session`, `propose-case`, and `resume` via
  `--record-transcript` / `--replay-transcript`, so an offline reproduction does not need
  Python glue or a provider credential.
- Documented the pattern in the runtime and architecture guides in addition to this bilingual
  PR note.

## Validation

```text
python -m unittest tests.test_runtime_transcript -v
python -m unittest tests.test_runtime_cli.RuntimeCliTests.test_run_can_record_then_replay_provider_transcript
python -m ruff check src tests
python -m ruff format --check src tests
python -m mypy src/contextopt
```

The provider-free tests cover record/replay round trips, cursor resume, request mismatch, and
tamper rejection. The cassette is intentionally an observation/debugging aid; it does not
pretend that a remote provider call was exactly once.

## Claim boundary

Recording proves only that a normalized response was durably written locally after the wrapped
model returned. Replay proves deterministic protocol reproduction for the same request sequence;
it does not measure model quality, provider reliability, latency, cost, or multi-agent value.
