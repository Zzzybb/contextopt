# v0.9 PR addendum: durable model-request idempotency hook

## What changed

- Added a deterministic key derived from `run_id`, turn, and the complete request SHA-256.
- `model.requested` events persist the key for audit and resume diagnostics.
- `OpenAICompatibleModel` sends the same key in `Idempotency-Key` by default and exposes
  `idempotency_header=None` for programmatic callers that must omit the header.
- The adapter configuration fingerprint includes the header choice, so a resume cannot silently
  change the provider boundary.

## Verification

- `python -m unittest tests.test_runtime_model tests.test_runtime_resume -v`
- `python scripts/ci_checks.py`
- `python -m unittest discover -s tests -q`

Tests verify stable keys across transport retries, different keys for different logical turns,
header propagation, and durable event recording.

## Boundary

The key is an interoperability hook, not a local exactly-once claim. A provider may ignore the
header, and a retry remains visible in the append-only ledger. Speculative solver lanes still have
their documented response-to-checkpoint crash window; provider-aware cancellation and winner
selection remain future work.
