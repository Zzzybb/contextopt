# v0.9 PR 补充：长程运行故障注入恢复矩阵

## 本次改动

- 新增 `recovery-eval` CLI 和五个确定性场景，覆盖 pending model request、已落账 model
  response、可 reconciliation 的写操作、已落账写结果以及不可重放的测试执行。
- 每个场景在目标 durable 事件之后绕过正常终态处理，随后用全新的 `AgentRunner`、
  `ScriptedModel` 和 `WorkspaceTools` 打开同一份事件日志恢复。
- JSON、Markdown 和自包含 HTML 报告记录 pending 状态重建、恢复前后事件序列、模型调用数、
  工具事件数、fixture 摘要，并明确 claim boundary。
- 新增协议 manifest、实验目录中英文说明，以及本 PR 的中英文变更说明。

## 验证

```text
python -m contextopt recovery-eval \
  --output experiments/v0.9-recovery-matrix/report.json \
  --markdown experiments/v0.9-recovery-matrix/report.md \
  --html experiments/v0.9-recovery-matrix/report.html \
  --manifest experiments/v0.9-recovery-matrix/manifest.json

python -m unittest tests.test_recovery_eval -v
python scripts/ci_checks.py
```

五个场景 `5/5` 通过。不可重放的 `run_tests` 场景会先得到 `paused`，只有显式
`mark_failed` 后才完成；已落账最终响应场景恢复时不会再调用模型；两个写操作场景都只
记录一次完成写入事件。

## 边界

矩阵证明的是当前覆盖范围内的本地恢复状态机和记账协议，不证明任意机器宕机恢复、恶意
替换 workspace/log、provider exactly-once 副作用、OS sandbox 安全性或真实模型代码能力。
模型是确定性的 `ScriptedModel`；真实 provider benchmark 仍需单独、明确版本化地运行。
