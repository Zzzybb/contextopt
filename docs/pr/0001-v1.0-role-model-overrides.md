# PR note: v1.0 role-specific model identities

## Why

The OpenAI-compatible factory already supported separate planner, solver, and reviewer model
names, but `AgentEvalConfig` did not persist those identities. A resumed matrix could therefore
silently switch one role's deployment while the checkpoint still appeared compatible.

## What changed

- Persist optional `planner_model`, `solver_model`, and `reviewer_model` in the agent-evaluation
  config and checkpoint fingerprint.
- Keep the identities in the provider manifest without storing credentials.
- Expose the same optional overrides in the manual GitHub Actions workflow and local CLI.
- Keep scripted and replay defaults backward-compatible; omitted overrides use the base model.

## Validation

```text
python scripts/ci_checks.py
python -m unittest tests.test_agent_search_eval
```

The local provider fixture already asserts role-specific request models and the new checkpoint
round-trip test asserts that all three identities survive serialization.

## Claim boundary

Role-specific model routing is an experiment-control and reproducibility feature. It does not
claim that a particular role decomposition improves real-model coding quality.
