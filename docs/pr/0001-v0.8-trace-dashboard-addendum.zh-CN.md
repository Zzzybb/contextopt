# v0.8 trace 可视化面板补充说明

## 本次范围

这次后续变更为持久化 runtime 事件日志增加只读可视化入口：

- `render_trace_html` 使用与 `render_trace` 相同的 JSONL 事件生成无依赖本地 HTML 时间线；
- 面板汇总事件数、模型请求数、工具结果数和 ContextReceipt 数；
- 每个事件都保留可展开、经过转义的 JSON payload，因此可视化不能替代审计源；
- `contextopt trace EVENT_LOG --html PATH` 写出面板，同时继续在 stdout 输出紧凑 trace；
- 测试覆盖 CLI 路径，并验证 context 与 model-request 事件可见。

## 为什么做

长程 Agent 出现问题时，如果能在一条时间线上扫描上下文选择、模型调用、工具观察和
恢复边界，定位会更快。这只是本地渲染层：不会修改日志、削弱 hash-chain 校验，
也不把 trace 当成模型质量证据。

## 验证证据

~~~text
python -m unittest tests.test_runtime_cli -v
python -m ruff check src tests
python -m mypy src/contextopt
python -m unittest discover -s tests -q
python scripts/ci_checks.py
~~~

## 边界

面板是现有事件源之上的调试和作品集视图，不是 OS sandbox、远程观测服务、学习型记忆
系统，也不是有统计功效的真实模型 benchmark。
