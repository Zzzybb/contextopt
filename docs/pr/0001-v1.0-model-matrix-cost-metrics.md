# v1.0 model-matrix cost metrics

## What changed

The matched multi-model Markdown and HTML renderers now expose the per-model, per-strategy
mean model calls, test calls, provider-reported tokens, and local duration next to visible and
hidden outcomes. The machine-readable JSON already retained these values; this change makes the
quality/cost trade-off visible in the portfolio dashboard without requiring a raw-ledger drill-down.

## Why

An agent strategy is not useful if it only reports a higher success rate while hiding extra calls,
tests, tokens, or wall-clock time. The comparison artifact must keep outcome and resource metrics
adjacent so an interviewer can inspect the trade-off and reproduce it from the same report.

## Validation

- `python -m unittest tests.test_model_matrix -v`
- `python scripts/ci_checks.py`
- `python scripts/run_model_matrix_demo.py --output-dir build/model-matrix-demo`

## Claim boundary

These are observed accounting metrics. Token counts come from the provider response when one is
used (or the deterministic control model), and duration is local wall-clock diagnostics. They do
not establish provider pricing, latency SLAs, model quality, causality, or production safety.
