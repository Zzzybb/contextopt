# PR 说明：v1.0 手动真实 provider 多模型矩阵

## 改动内容

- 新增 `.github/workflows/real-agent-model-matrix.yml`，手动触发，对至少两个带 label 的模型
  使用相同的 `agent-eval` 协议运行矩阵。
- 在创建 job matrix 之前校验 JSON 模型列表、安全的 artifact label、重复 label，以及至少三次
  配对 repetition 的预算门槛。
- 为每个模型分别保存 manifest、checkpoint、HTML/Markdown 报告和 provider transcript cassette，
  最后在独立 job 中调用 `agent-eval-compare`，上传机器可读和 dashboard 对比产物。
- 在中英文真实 provider 评测文档和本双语 PR 说明中记录运行方式。

## 为什么做

之前的手动 workflow 一次只生成一份 provider bundle，第二份 bundle 和协议校验分析需要操作者
手工完成。现在跨模型实验本身也可复现：endpoint、角色覆盖、fixture、策略、预算、sandbox、
revision 和 repetition 对所有 cell 共享，模型身份则保留为有意变化的自变量。

## 验证

~~~text
python scripts/ci_checks.py
python -m unittest discover -s tests -p 'test_*.py'
~~~

测试套件包含 workflow contract 测试，用来锁定手动 fan-out、secret 边界、transcript 记录和
最终 artifact 汇总。workflow 仍然是手动触发，并要求显式配置 `CONTEXTOPT_API_KEY` secret；
普通 CI 不会触发它，也不会访问 provider。

## 结论边界

本改动增加的是编排和产物管线，不是真实模型能力证据。最终 `agent-eval-compare` 仍是固定的、
小样本的描述性比较；它会拒绝协议漂移，但不能证明泛化能力、统计功效、provider 稳定性、延迟
保证、远端取消或生产安全。只有操作者用获授权的 endpoint 运行 workflow 并检查上传产物后，才
存在真实 provider 结果。
