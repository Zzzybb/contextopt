# PR #1 — v0.9 automatic semantic-context evaluation

## Why

The opt-in `versioned-v1+semantic` runtime path now has a provider-free conformance
matrix. This keeps the important claim boundary explicit: we can prove that durable
memory candidates are retrieved, budgeted, and replayable, but we cannot call that
model quality without an authorized real-provider run.

## What changed

- Added `contextopt semantic-context-eval` with fixed ACM/math memory fixtures.
- Runs `recent`, `topk`, `density`, and `submodular` across deterministic token budgets.
- Records retrieved/selected ids, fixture-label recall, candidate token estimates,
  evictions, budget compliance, receipt determinism, and store-free replay.
- Added JSON, Markdown, and self-contained HTML renderers plus unit/CLI tests.
- Added a CI smoke invocation and checked-in bilingual artifacts under
  `experiments/v0.9-semantic-context/`.

## Claim boundary

The evaluator makes zero model calls. Its recall is exact retention of a hand-labelled
fixture memory id, not embedding quality, semantic understanding, model-use evidence,
or coding-task success. Real-provider multi-round evaluation remains a separate,
explicitly authorized step.

## Verification

```text
python -m contextopt semantic-context-eval --repetitions 2 --budgets 128,512
python -m unittest tests.test_semantic_context_eval -v
```
