# v0.8 有界 MCTS 调度器补充说明

## 本次范围

这次后续变更在保留 `beam` 可复现基线的前提下，加入第二种可审计的分支选择策略：

- `BranchSearchConfig.search_policy` 接受 `beam` 或 `mcts`，`exploration_constant` 会随报告
  一起持久化；
- `mcts` 在已经生成的、带 parent 链的 `CandidatePatch` 树上做确定性的 UCT 遍历；先探索
  未观测子节点，再把 visible-test 质量沿选中的父链回传；
- 每次选择都会写出 `candidate.selected`，包含父节点/候选访问次数、UCT 分数（首次探索时
  显式为 null）和候选 value；rollout 与终态事件继续进入原有 hash-chain；
- 工作区 fingerprint 去重、候选/深度/测试预算、`stop_on_pass` 和可信 executable oracle
  边界保持不变；
- `branch-search`、`search-session`、`orchestrate`、`agent-eval` 都支持
  `--search-policy mcts`，HTML/Markdown/console 报告会显示所用策略。

## 为什么做

之前的 adaptive 调度器已经会根据父分支质量选择下一批并行候选，但纯分支核心仍然只有
beam 排序。MCTS 把树策略显式化，面试时可以具体解释长程搜索：观测结果进入有界状态，
reward 回传到祖先，每次选择都能从 ledger 重放。它不会让模型自报 reward，也不会执行
不受控的 merge。

## 验证证据

确定性测试构造三个质量不同的根假设，并断言根节点探索后 MCTS 会选择最高质量父节点的子节点；
同时验证报告确定性 round-trip、选择事件字段、CLI 接线和完整门禁：

~~~text
python -m unittest tests.test_branch_search -v
python -m unittest tests.test_search_session tests.test_orchestrator -q
python -m contextopt agent-eval --fixtures all --repetitions 1 --search-policy mcts
python -m ruff check src tests
python -m mypy src/contextopt
python -m unittest discover -s tests -q
python scripts/ci_checks.py
~~~

## 边界

这是固定候选图上的有界 UCT，不是按需生成候选的 PatchTree、投机式模型调用、支持 merge
冲突的多 Agent 搜索，也不是安全 sandbox。reward 只来自 visible-test `quality_score`，
hidden grader 永远不参与调度。脚本 fixture 只能证明调度 accounting 和可重放性，不能证明
模型编码能力、泛化、provider 稳定性或生产安全。
