# PR 说明：v1.0 可选 Docker 候选执行 sandbox

## 为什么做

宿主机进程清理和凭据清理可以减少意外泄露，但不是 OS security boundary。受控的真实模型
代码评测需要一种可重复的方式，把 visible/hidden 候选 grader 放到宿主机文件系统和网络之外运行。

## 改动内容

- 增加 `ExecutableSearchConfig(sandbox="docker", container_image=...)`，并为 branch search、
  search session、orchestration、`agent-eval` 增加对应 CLI 参数；
- Docker 命令使用 `--network=none`、`--read-only`、`--cap-drop=ALL`、
  `--security-opt=no-new-privileges`、pids 限制、有限内存/CPU、小型 `/tmp` tmpfs，以及唯一可写的
  `/workspace` bind mount；
- ACM/数学 visible/hidden grader 在容器内使用 `python`，不再使用宿主机绝对解释器路径；
- 为容器生成唯一 name，超时后强制删除；宿主机进程组/Windows Job Object 仍作为外层生命周期保护；
- execution/evaluation checkpoint 保存 sandbox/image identity，resume 不能静默切换执行边界。

## 验证命令

```text
python -m unittest tests.test_branch_executor tests.test_agent_search_eval -v
python scripts/ci_checks.py
```

本地 CI 主机没有 Docker，因此测试覆盖显式配置和运行时缺失错误路径；真正的 Docker 运行需要在
启用 Docker 的 runner 上执行。GitHub Actions 的 `docker-sandbox` job 会在带 Docker 的 Ubuntu
runner 上用 `python:3.12-slim` 真实启动同一个 adapter；如果容器路径无法执行候选就会失败。

## 结论边界

这是可选的受控执行路径，不保证每种部署都安全。操作者仍需固定并审查镜像、Docker daemon、挂载
策略和宿主 runner。默认仍是可信宿主机进程；provider-free CI 不声称真实 provider benchmark。
