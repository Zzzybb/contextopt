# v0.9 后续 — 可选的语义记忆上下文候选

## 摘要

之前的 durable memory 只能通过显式 `memory_search` tool 调用读取。本次增加一个有界、显式
opt-in 的上下文投影，让跨运行经验可以参加普通上下文选择，同时不把它变成强制 prompt 文本
或不可审计的旁路。

## 改动

- 单 Agent 上下文策略新增 `versioned-v1+semantic`。挂载 `SemanticMemoryStore` 后，每轮按
  当前任务检索最多 3 条 lexical 命中；`--memory-scope` 可限制项目 scope，但仍保留 `global`。
- 命中会渲染成带标签的 advisory assistant block。它们是普通上下文候选，带有 confidence、
  matched-term、tag 和 freshness 信号，继续由 `submodular`、`density`、`topk` 或 `recent`
  在原有估算 token 预算中选择或淘汰。
- `ContextFrame.metadata` 增加候选 id、实际选中 id、完整 match 快照和 durable-store
  fingerprint。组合后的 memory fingerprint 同时覆盖本轮 observed ledger 与 durable store。
- recovery 和挂起请求 resume 都能从 receipt 快照重建候选。进程停止后即使 live store 变化，
  pending request 仍会重放原始候选消息和已经记录的 request hash。
- 默认 `versioned-v1` 行为保持不变：除非调用方显式选择新策略，否则语义记忆仍需模型主动
  调用工具。

## 结论边界

这是有界上下文工程，不是学习型 retriever，也不证明记忆会提升代码成功率。检索仍是无需
provider 的 lexical 匹配；候选只是 advisory，必须结合当前 workspace 证据验证。receipt 能证明
哪些候选可用、哪些被选中，但不能证明模型正确使用了它们。
